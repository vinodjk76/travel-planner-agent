# CrewAI Multi-Agent Travel Planner

An autonomous multi-agent orchestration workflow built on **CrewAI** and **LangChain**. This application automatically divides travel planning responsibilities across three specialized AI agents to generate structured, personalized itineraries and complete itemized cost analyses based on user-defined inputs.

---

## 🏗️ Architecture & Component Workflow

The application leverages a sequential execution architecture. The output context generated by earlier tasks is automatically passed as an entry vector to downstream agents, simulating a real-world professional collaborative workspace.

## ⚙️ Setup & Installation Instructions

Follow these step-by-step commands from your project root folder to install dependencies and configure local runtimes:

### 1. Provision Your Virtual Environment
```bash
# Create a local virtual isolation layout
python -m venv .venv

# Activate on Windows (PowerShell)
.venv\Scripts\Activate.ps1

# Activate on macOS / Linux
source .venv/bin/activate
```

### 2. Install Project Dependencies
```bash
pip install -r requirements.txt
```

### 3. Establish Runtime Environment Variables
Create a file named `.env` in the project root directory and add your secret credentials:
```text
OPENAI_API_KEY=sk-proj-your_actual_secret_openai_key_here
CREWAI_TELEMETRY_OPT_OUT=true
```

## 🚀 Usage

Execute the pipeline interface script via your console, providing parameters using CLI arguments:

```bash
python main.py --destination "Tokyo, Japan" --days 5 --budget 2000 --interests "food, anime, ancient history"
```

### Command Flags:
* `--destination`: (Required) The destination city and country context string.
* `--days`: (Required) An integer defining the exact duration of the schedule.
* `--budget`: (Required) A floating-point number setting the strict financial limit in USD.
* `--interests`: (Optional) Core traveler preferences. Defaults to `"general sightseeing"`.

## 🧪 Running Automated Tests

A dedicated test suite validates path compliance, decorator parsing mapping, and execution isolation using mocked dependencies to ensure no network tokens are consumed during building cycles.

Execute the test engine directly from the root workspace directory:
```bash
python -m unittest discover -s tests
```
